I taught my AI to remember things.

For two months I'd been watching the same fixable mistakes happen over and over. Same Railway trap. Same Postgres error swallowed. Same scope quietly narrowing. So I rebuilt how my AI ships.

The problem

Every session, the same mistakes — different costume.

I'd written down the lessons. They sat in 78 memory files and 12 distilled patterns. My AI just... never read them. Four leaks I could name:

i.

Patterns get skipped

Rules I'd written down weren't getting applied — agents had no instruction to read them.

ii.

Project gotchas re-surface

The same Railway trap, the same Supabase quirk — re-derived every session because nobody read the file.

iii.

New lessons evaporate

Surprises during a build never made it back into memory. The discipline assumed I'd stop and write them down. I didn't.

iv.

The pipeline is just a list

My ship command was twelve lines of "do this, then this." No checks. No enforcement. No closing the loop.

Memory exists. The AI just doesn't read it. The fix isn't more agents — it's making the ones I have aware of what I've already learned. — what I told myself the morning I started this build
What I built

A pipeline that reads its own homework.

/ship is now eleven stages. Three of them new. One of them gated by a hook so I literally can't skip it.

Before any agent runs, a small Haiku-powered assistant called memory-keeper detects the project, reads the request, and pulls in the handful of lessons that actually apply. It writes a small file called patterns.md. Every downstream agent reads it before doing anything.

At deploy time, a hook — ship-phase-gate.sh — counts deploy attempts in real time. Three pushes without a stated pivot? Blocked. Logs not visible? Warned. No smoke test? Warned. The discipline is mechanical now.

At the end, memory-keeper comes back. It scans the session for moments where I corrected the AI, drafts feedback files, asks me three questions, and stores what I approve. The next ship reads those.
